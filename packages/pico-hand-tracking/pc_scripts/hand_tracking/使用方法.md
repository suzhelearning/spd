# PICO Hand Tracking 有线 ADB 推流

Unity 端新增脚本为 `Assets/Scripts/PicoHandTrackingAdbStreamer.cs`。它只读取头显位姿和 PICO Hand Tracking 26 个关节，不采集相机，也不会向 PICO 回传视频。

## Unity / PICO 设置

1. 在 `SampleScene` 的一个常驻对象上挂载 `PicoHandTrackingAdbStreamer`。同一个对象上不要同时启用会占用相同 TCP 端口的旧推流脚本。
2. 在 PICO Unity Settings 中打开 Hand Tracking（或把 PICO Hand Tracking Building Block 加入场景）。脚本使用 SDK 3.4 的 `PXR_HandTracking.GetJointLocations`。
3. `tcpPort` 默认是 `10002`。如果脚本挂在 XR Origin 根对象，脚本会自动寻找名为 `Camera Offset` 的子节点作为 `trackingSpace`；否则把手部 API 所属的追踪空间手动拖入该字段。坐标看起来已经正确时保持为空即可。
4. `drawSkeleton` 默认开启。左手骨骼为绿色，右手为蓝色；线宽可以在 Inspector 调整。

应用启动后，脚本拿到第一帧有效头显位姿时锁定世界参考。参考位置成为 FLU 原点，参考头显的水平朝向成为 X 前向；俯仰和横滚被去除，以保证 Z 轴始终指向重力反方向。所有发送位置、姿态和骨架关节均已是 FLU 坐标。

## 启动时提示“本地缓存中没有权限信息”

这个提示是 PICO 平台的应用授权（entitlement）/联网缓存检查，发生在 TCP 服务和 Hand Tracking 初始化之前，不是 ADB 转发失败。首次启动或缓存过期时，请按下面顺序处理：

1. 让头显本身连接可访问互联网的 Wi‑Fi 或手机热点，并在头显中完成 PICO 账号登录；保持联网状态启动一次应用，让平台写入本地授权缓存。
2. 如果这是 Unity 本地开发 APK，在 `PICO > Platform > Platform Settings` 中关闭 `User Entitlement Check`（用户授权检查）。当前工程的 `PXR_PlatformSetting.asset` 已保持 `startTimeEntitlementCheck: 0`、`entitlementCheckSimulation: 0`。只有上传到 PICO 开发者平台并配置有效 AppID 的正式包才应打开它；不要为了绕过检查填写虚构的 AppID 或设备序列号。若头显仍弹此窗，通常是正在运行旧 APK，或被 PICO 系统级授权策略拦截。
3. 重新构建并安装当前工程的 APK。工程已开启 `handTracking`，并选择 `HandsOnly`（`handTrackingSupportType: 1`）；旧 APK 不会包含新的 Hand Tracking manifest 权限。可用下面命令确认安装包的权限列表：

   ```bash
   adb shell dumpsys package com.PICO.hand.tracking.wired.unity | grep -i hand_tracking
   ```

4. 应用能正常进入场景后，再启动 PC 接收脚本。接收脚本默认会自动执行 ADB 转发；如果头显仍停留在系统授权弹窗，先查看 `adb logcat | grep -i entitlement`；网络/账号、AppID、授权缓存过期都需要在 PICO 平台侧处理，PC 端脚本无法替代该授权。

## ADB 与接收

先确认设备已经授权。接收脚本启动时会自动执行 `adb forward tcp:10002 tcp:10002`，PICO 重启或 USB 重新连接后也会在重连前再次执行：

```bash
adb devices
```

启动 APK 后运行：

```bash
python pc_scripts/hand_tracking/pico_hand_tracking_receiver.py --port 10002 --print
```

如果电脑同时连接多个 Android/PICO 设备，指定序列号：

```bash
python pc_scripts/hand_tracking/pico_hand_tracking_receiver.py \
  --port 10002 --adb-serial PA921BMGL3190346G --print
```

如果 ADB 转发由其他程序统一管理，可关闭脚本内置转发：

```bash
python pc_scripts/hand_tracking/pico_hand_tracking_receiver.py \
  --port 10002 --no-adb-forward --print
```

需要 3D 实时查看时安装桌面可视化依赖，并运行。Ubuntu 24.04 请使用独立虚拟环境，避免 PEP 668 限制：

```bash
python3 -m venv .venv-hand-tracking
.venv-hand-tracking/bin/python -m pip install pyqtgraph PyQt5 PyOpenGL numpy matplotlib
.venv-hand-tracking/bin/python pc_scripts/hand_tracking/pico_hand_tracking_receiver.py \
  --port 10002 --visualize --print
```

`--visualize` 默认打开一个独立的深色 Dashboard 窗口：顶部显示头部和左右手的数据卡片，中间显示 3D 网格、世界原点、彩色 XYZ 三轴（X forward / Y left / Z up）、手指骨架和头部朝向箭头，视角固定在头部后方（FLU 的 -X 方向）并向上倾斜约 16°。窗口不会随鼠标拖动改变视角，便于连续观察。若只需要旧版 Matplotlib 视图，可显式使用 `--visualize-mpl`：

```bash
python pc_scripts/hand_tracking/pico_hand_tracking_receiver.py --port 10002 --visualize-mpl --print
```

如果 Dashboard 依赖未安装，脚本会自动回退到 Matplotlib，并优先加载与当前 Matplotlib 版本匹配的 `mpl_toolkits.mplot3d`，可处理 Ubuntu 系统包和用户目录 pip 包混装导致的 `Unknown projection '3d'`。`pyqtgraph.opengl` 还需要额外安装 `PyOpenGL`。建议使用上面的独立 Python 环境，避免混用 `/usr/lib/python3/dist-packages` 和 `~/.local/lib/python3.x/site-packages`。

如果系统尚未提供 `venv` 模块，先安装：

```bash
sudo apt install python3-venv
```

也可以保存解码后的完整数据（包含四元数、关节有效标志和半径）：

```bash
python pc_scripts/hand_tracking/pico_hand_tracking_receiver.py \
  --port 10002 --save-jsonl ./hand_tracking.jsonl
```

接收脚本会在 PICO 重启或 USB 断开后自动重连。`--visualize` 使用固定的头部后方视角（FLU 的 -X 方向，向上倾斜约 16°），视野中心略微放在头部前上方，双手移动时画面不会跟着旋转；窗口使用深色面板、左右手高对比配色、头部朝向箭头和状态卡片，坐标轴标注为 X forward、Y left、Z up。

打印中的 `hands=L0/R0` 表示该帧没有通过 PICO 的手部有效性判断；对应腕部坐标会填零，不代表手腕真的位于 FLU 原点。把手放到头显可见范围后会变为 `L1` 或 `R1`，再显示对应腕部和 26 个关节。

频率说明：PICO 高速手势追踪的官方上限是 60 Hz，因此数据发送和 Unity 主循环默认均为 `60`：`sendRateHz=60`、`targetUnityFrameRate=60`。发送调度使用累积 deadline，避免小幅帧时间抖动导致长期降频。PICO 显示屏仍可配置为 90 Hz，但显示刷新率不等于手部数据发送频率。脚本启动时会关闭 VSync，并尝试 CPU/GPU BOOST；这些设置会在启动后 0.5/1.5/3/5 秒再次应用，以覆盖 XR 初始化阶段的覆盖。

PC 端打印行里的 `rx=xx.xHz` 是接收端实测值，应该以它为准（头显和手至少有效后观察 10 秒）。`--print` 只按约 4 Hz 输出文字，3D 窗口约 60 Hz 刷新并显示最新一帧，因此文字/窗口刷新频率不等于数据接收频率。稳定运行时 60 Hz 主循环应接近 60 Hz 数据流；如果 Unity 丢帧、PICO 手部 API 没有新样本或追踪服务降频，实际值会低于 60 Hz。请确认使用重新构建后的 APK，并查看 `adb logcat` 中的 `[PicoHandTracking] runtime target=...` 日志。

为降低高频追踪下的 GC 抖动，发送帧现在使用固定大小缓冲池，避免每帧同时创建 payload 和完整 TCP frame 两个数组；队列仍保持 latest-first 丢帧策略，网络慢时不会反向阻塞 Unity `Update`。手部 API 按发送频率轮询，默认不超过 60 Hz；场景在 Hand Tracking 模式下会关闭不相关的 `PicoControllerTracker`。PICO 画面骨骼绘制仍保留 50 条 `LineRenderer`；如果需要确认采样瓶颈，可临时关闭 `drawSkeleton` 做一次对照测试。

## 二进制协议

每帧头部为 `[0xAB][type:1][timestamp_ms:int64 LE][payload_length:uint32 LE]`，本功能的 `type` 是 `0x40`。payload 长度为 1968 字节：

```text
uint8 version=1, uint8 flags, uint8 joint_count=26, uint8 reserved
head pose: 7 x float32                 # position xyz + quaternion xyzw
left:  valid + reserved[3] + wrist pose + 26 joints
right: valid + reserved[3] + wrist pose + 26 joints
joint: valid + reserved[3] + pose + radius(float32)
```

`flags` 的 bit 0/1/2 分别表示头显、左手、右手当前是否有效。关节顺序与 PICO `HandJoint` 枚举一致：palm、wrist，随后 thumb/index/middle/ring/little 的 metacarpal、proximal、intermediate、distal、tip。
